# AI 任务书（briefs）—— 一次性工作文件，**用完即删**

**这里的东西不留档。**

理由：任务书写的是"当时打算怎么改"（**意图**），不是"代码现在是什么样"（**事实**）。改完提交后意图就过期了，
留着它只会让后来的人或 AI 拿过期意图当事实 —— 这是最隐蔽的一类幻觉来源（用户 2026-10-15 明确要求全删）。

## 规矩

1. **进行中**的任务书写在本目录根下：`<ID>_brief.md`（ID 例：`P1-6`、`T2`、`LB1`、`SF1`）。
2. **该项提交后立即删除**：`git rm docs/reviews/briefs/<ID>_brief.md`，与该修复**同一个提交**。不归档、不留底。
3. **被取代的**（写完没用上、或拆成几步后旧的）当场删。
4. **要留的是结果，不是施工单**：
   - 改了什么 / 为什么 / 怎么验证的 → `../FIX_LOG.md`（权威记录）
   - 现在的代码长什么样 → 代码本身 + 各模块 `.md` 的「实现架构」章
   - 平台的坑与硬约束 → `../../references/`（例：`LLCC68_E220-900M22S.md`）

## 任务书模板（越具体越不跑偏）

1. **背景**：贴原代码片段 + 说清后果（为什么非改不可）。
2. **允许改动的文件**：白名单逐条列，其它一律不动。
3. **逐条改法**：到函数 / 行 / 新代码原文。
4. **自检问题**：3~4 个「为什么」，逼 AI 讲清依据。
5. **完成后报告**：改动摘要 + 自检结论 + **诚实列出"本次改动不能保证什么"**。

调度时固定附加这句：

> *只允许改动任务书列出的文件；不要改任何 `.md`；不要跑 `pio`/编译；不要 `git add/commit`；只在仓库目录内活动（不要读 `/tmp`、`~/.platformio` 等仓库外路径）。*

## 环境提醒

- 命令：`bash ~/.local/bin/oc-deepseek '<调度提示词>' -f docs/reviews/briefs/<ID>_brief.md`
- **任务书必须放在仓库内**（就是这个目录）：OpenCode 对工作目录以外的读取会**自动拒绝**并终止任务。
- 改代码前先看平台硬约束：`../../references/LLCC68_E220-900M22S.md`。

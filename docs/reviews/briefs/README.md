# AI 任务书（briefs）

**权威记录不是这里的任务书，而是 `../FIX_LOG.md`**（条目 → 提交号 → 改了什么 → 怎么验证的 → 遗留）和各模块 `.md` 的实现章节。
任务书只用来追溯"当时是怎么要求 AI 改的"，所以**已完成的一律归档到 `archive/`，不留在根目录**（否则目录会变成垃圾场）。

## 规矩

- **进行中**的任务书写在本目录根下：`<ID>_brief.md`（ID 例：`P1-6`、`T2`、`LB1`、`SF1`）。完成后随该项的提交一起 `git mv` 进 `archive/`。
- **已被取代的任务书直接删掉**，不留树里（例：`A5_brief` 被 A5a/A5b 取代、`SA_brief` 被 SA2 取代、`FB_brief` 被 FB2 取代 —— 均已删）。
- 只读类任务（静态排查等）的描述也走这里，但**结论**要写进 `../` 的审查报告。

## 任务书模板

必须含（越具体越不跑偏）：

1. **背景**：贴原代码片段 + 说清后果（为什么非改不可）。
2. **允许改动的文件**：白名单逐条列，其它一律不动。
3. **逐条改法**：到函数 / 行 / 新代码原文。
4. **自检问题**：3~4 个「为什么」，逼 AI 讲清依据。
5. **完成后报告**：改动摘要 + 自检结论 + **诚实列出"本次改动不能保证什么"**。

调度时固定附加这句：
> *只允许改动任务书列出的文件；不要改任何 `.md`；不要跑 `pio`/编译；不要 `git add/commit`；只在仓库目录内活动（不要读 `/tmp`、`~/.platformio` 等仓库外路径）。*

## 环境提醒

- 命令：`bash ~/.local/bin/oc-deepseek '<调度提示词>' -f docs/reviews/briefs/<ID>_brief.md`
- **任务书必须放在仓库内**（就是这个目录）：OpenCode 对工作目录以外的读取会**自动拒绝**并终止任务。
- 平台硬约束（改代码前先看）：`../../references/LLCC68_E220-900M22S.md`。

# EMlink 任务书 T-3：计数按三层归集，`status` 改成分层显示（三件最疼之二）

## 背景（为什么改）
A/B 档把每层的丢弃/错误计数补得差不多了，但 **`status` 现在是"按加的先后顺序"堆出来的十三行**——上板调试时看一屏数字，**分不清是驱动丢的、中间件丢的还是应用丢的**，也不知道该往哪层查。
砍掉重复信息、按 **驱动 / 中间 / 应用** 三层重新组织这一屏，让"哪一层出问题"一眼可见。这是纯展示层重构：**不加任何新计数、不改任何计数值、不动任何模块的统计逻辑**。

## 允许改动的文件（其它一律不碰）
1. `firmware/src/app/cli.cpp`
不要改任何 `.md`；不要运行 pio/编译；不要 git commit/add。

### 分层归属（按此表组织，并在代码里用注释写清"为什么归这层"）
| 归属 | 计数 |
|---|---|
| **驱动层** | 收包队列丢（`radio_rx_drop_count`）、射频请求丢（`radio_req_drop_count`）、UART 丢（`uart_fc_drop_count`）、USB 丢（`usb_cdc_drop_count`）、射频就绪（`radio_is_ready`） |
| **中间层 · 链路** | 占空比超限放行（duty）、认证失败（`mesh_drop_auth_count`）、重放丢弃/重同步（`crypto_replay_drop_count`/`crypto_replay_resync_count`）、限流丢弃/控制类/超桶（`ratelimit_drop_count`/`ratelimit_ctrl_drop_count`/`ratelimit_oversize_count`）、协议不一致（`mesh_proto_mismatch_count`） |
| **中间层 · 网络** | 去重淘汰（`mesh_dedup_evict`）、TTL 丢弃、路由过期/淘汰、地址过期/淘汰、分片槽淘汰、**发送队列丢（`rtos_tx_drop_count`，归中间层：它反映的是中间层消费不过来造成的背压）** |
| **中间层 · 速率** | ADR 对齐状态/信标/多跳/失步/多锚点/SF（`adr_*`） |
| **应用层 · 流量** | 遥测降频（`mav_router_stream_drop_count`）、sysid 撞号、node_id 撞号 |
| **应用层 · 系统** | heap、看门狗复位计数、射频重建计数（来自 `stats_t`） |

> 若某个计数你判断归属存疑（例如"发送队列丢"），按上表执行，并在代码注释里写明理由（这也是给人看的契约）。

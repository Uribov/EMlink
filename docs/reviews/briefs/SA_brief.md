**这是只读任务：禁止创建、修改、删除任何文件；禁止任何 git 命令；禁止运行 pio/编译。**

## 背景
固件已完成一轮产品级审查（`docs/reviews/CODE_REVIEW_2026-10-14.md`），修了 M0/A/B 共 19 项 + M2 若干项，**全部只到"编译通过"**，从未上板。板子未到。

## 待扫的 8 类（逐类给出：候选清单 + 初判 + 若判为真 bug 则写"最小修法建议"但**不要改**）

### 类 1：定时器时基假设
`frag_tick()` / `adr_tick()` / `radio_retry_tick()` / `ota_boot_confirm_tick()` 等"周期性 tick"函数，**其调用条件是否真的保证周期性**。
- **已知样例（不必重复报告，请找同类）**：`net/mesh.cpp:376-382` 里 `frag_tick()` 只在 `xQueueReceive` **超时**分支执行 → 链路一忙、帧连续到达时永不执行。
- 请逐个核对：每个 tick 函数的**所有调用点**（`grep -rn "_tick()"`），判断"在什么条件下会跑、什么条件下不跑"；特别是"只在收到东西时才跑"或"只在某个分支才跑"的情形。
- 另外看：tick 内部用 `millis()` 自己算时间（安全）还是**依赖调用次数/调用间隔**（危险）。

### 类 2：时间比较的回绕安全
`millis()` 全仓 41 处，其中仅 8 处用 `(int32_t)` 有符号差值、3 处显式 `(uint32_t)(now - …)`。
- 逐处分类：**赋值**（`x = millis()`）不算问题；**比较**（`a - b > X`、`millis() - g_x > X`）才要判断。
- 判据：跨回绕（约 49.7 天）或"重启后时间戳比基准小"时，该比较是否会得出错误结论。

### 类 3：任务栈够不够
栈：`RF/MAC/MESH/UART/USB/CLI = 4096`、`MAVLINK/OTA = 8192`、`STATS = 2048`（见 `rtos.h`）。
- 对每个任务函数（`*_task_func`）：找出其**最大局部数组/结构体**（全仓 26 处 `char buf[n]`、28 处 `memcpy`、21 处 `memset`）与**调用深度**，估算栈占用，判断是否逼近栈大小。
- 特别看：`cli`（`char line[384]` 等）、`ota`（WebServer/HTML）、`mav_router`（分片缓存是 static 还是局部？）、`mesh`（`frame_t` + 缓冲）。

### 类 4：无限等待 / 阻塞在关键路径
`portMAX_DELAY` **3 处**、`xQueueReceive` 10 处、`vTaskDelay` 14 处、Arduino `delay()` **4 处**。
- 判据：出现在"必须按节拍跑"的任务里（rf / mac / mesh）→ 卡住会连带看门狗与心跳；出现在 CLI/OTA 等"人可以等"的任务里 → 可接受。
- 逐处说明属于哪一类任务、结论。

### 类 5：中断上下文
`IRAM_ATTR` 1 处、`attachInterrupt` 2 处。
- 核对 ISR 里是否只做了 ISR-safe 的事（发任务通知/置标志）；是否出现打印、阻塞队列、长循环、非 IRAM 函数。
- 另看：ISR 里访问的变量是否 `volatile`；是否有"漏清中断标志"的可能。

### 类 6：算术与边界
- `/` 运算 42 处，其中**变量作除数 12 处** → 逐个判断能否为 0（尤其 `x / (a - b)`、`len / n`）。
- `uint8_t/uint16_t` 自增累计 **4 处** → 溢出后被当成"数字变小"（比较/减法用错）的风险。
- 有符号/无符号混用比较：`(int)` 与 `unsigned` 比较、`sizeof()` 参与的比较。
- 数组下标：是否有用计算值/网络来的值直接索引数组（可能越界）的地方。

### 类 7：动态内存
grep 命中 `malloc/calloc/free` **2 处**（怀疑是 `heap_free` 之类变量名误报）→ **确认这两处到底是什么**；若确有动态分配，指出位置与风险。

### 类 8：跨任务共享变量
`portMUX` 临界区 24 处、`volatile` 23 个、EventGroup 10 处。
- 找出"被两个及以上任务读写的变量"但**既非 volatile 也无临界区保护**的。
- 找出**临界区未闭合**的（`portENTER_CRITICAL` 后中途 return/continue 漏了 `portEXIT_CRITICAL`）。
- 找出"读-改-写"不原子的计数器（预期大多是"只增只读、允许近似"，属于可接受——但要写明）。

# 开机操作卡（板子到货第一天照这个走）

> 给第一次上板用。每步都写了原因和应该看到什么，出问题照着「常见现象对照表」查。
> 更完整的验证清单在 `../todo.md`；这份只覆盖「第一天开机」。


---

## 0. 先备齐

- [ ] 至少 2 块板（一块 GCS、一块 AIR；单块只能看开机，通联测不了）
- [ ] 两根 USB 数据线（注意：充电线没有数据线芯，接上电脑不认串口，这是新手最常踩的坑）
- [ ] 天线：SMA/IPEX 天线先拧上再上电。空载发射可能烧功放 —— 这条没有例外
- [ ] 电脑上装好 `pio`（PlatformIO）和串口工具（`picocom`/`minicom`/`screen` 任选）

四件缺一样都会卡在第一步，先把东西凑齐再动手。

## 1. 串口权限

```bash
sudo usermod -aG dialout $USER     # 加进 dialout 组
# 然后注销/重新登录（组权限要重新登录才生效）
ls /dev/ttyUSB* /dev/ttyACM*       # 插上板子后应该能看到设备
```

> 看不到设备 = USB 线是充电线 / 板子没供电 / 驱动没装。先解决这个，别的都别急。

---

## 2. 烧固件（必须整片擦除）

```bash
# 单块板（第一次）
cd /home/sun/EMlink
bash tools/flash_batch.sh --port /dev/ttyUSB0

# 多块板一起刷（可选）
bash tools/flash_batch.sh --all
```

- 必须整片擦除的理由：分区表改过（OTA 双分区），不擦会起不来或行为怪异
- 全网必须同版本的理由：帧头从 14 字节改成 15 字节过，新旧固件不兼容，混刷就是「怎么都通不上」
- 卡住不动 / 报连不上：按住板上的 BOOT 键再插 USB（进下载模式），刷完拔插一次

## 3. 开机看什么（USB-C 那一个口，115200）

```bash
picocom -b 115200 /dev/ttyUSB0      # 退出：Ctrl-A 再 Ctrl-X
```

> 日志和命令都在这一个口上（`platformio.ini` 里 `ARDUINO_USB_CDC_ON_BOOT=1`，`Serial` = USB 虚拟串口）。
> 注意：这是板子上的 USB-C，不是飞控串口；飞控那边是另外两个焊盘脚（GPIO43/44）。

- 停在 `===== 就绪 =====` = 启动正常
- 每隔 5 秒重启一次 = 看门狗在咬人（这个 bug 已修，若复现说明刷的不是最新固件）
- 没有任何输出 = 波特率不对 / 线不对（充电线没有数据线芯）/ 没擦干净 / 板子没起来 → 回到第 1、2 步

### 3.1 两分钟自检

```
1) 看到 "===== LoRa Mesh 数传 boot =====" 和 "===== 就绪 ====="   → 启动 OK
2) 敲 help，应该有命令列表回显                                    → CLI 通路 OK（关键！）
3) 敲 ver，应显示：EMlink 固件 0.1.0 · 协议 v2                     → 版本 OK
4) 敲 status，应看到三层分组（驱动层/中间层/应用层）                → 观测 OK
```

第 2 步是分水岭：能看到日志但敲命令没反应 = CLI 通道没通（固件是修复前的版本），此时别急着怀疑射频 —— 先把固件刷成最新版再试。若已是最新版仍无回显：拔插一次 USB 再试（一次误判的「半截帧」会让分流等 500ms 自恢复）。

## 4. 三条命令先敲一遍

```
ver        # 看固件版本 + 协议版本：应显示 EMlink 固件 0.1.0 · 协议 v2
status     # 分层状态：驱动层 / 中间层 / 应用层，各层丢了多少
help       # 全部命令
```

`status` 怎么读（这是本项目的核心调试工具）：

```
=== 状态 ===
角色: air   node_id=7   sysid=1   名字=air-01   协议: 本机=v2 对端=v2
--- 驱动层 ---      ← 板子/接线/射频模块这一边界有没有丢东西
射频: 就绪=是  收包队列丢=0  射频请求丢=0  UART丢=0  USB丢=0
--- 中间层 ---      ← 链路协议/转发/限流这一层有没有丢东西
链路: 占空比超限放行=0  认证失败=0  重放丢弃=0  重同步=0  限流丢弃=0(控制类0/超桶0)  协议不一致=0
网络: 去重淘汰=0  TTL丢弃=0  路由过期=0/淘汰=0  地址过期=0/淘汰=0  分片槽淘汰=0  发送队列丢=0
速率: ADR 对齐=是  信标=12  多跳=0  失步=0  多锚点=0  SF=7  beacon_s=5
--- 应用层 ---      ← 应用主动削减的流量、编号冲突、整机资源
流量: 遥测降频=0  sysid撞号=0  node_id撞号=0
系统: heap=184320  wdt复位=0  射频重建=0
```

一句话读法：三组都全 0 = 这一层没丢东西。哪一组涨，问题就在哪一层。

## 5. 让两块板通起来

1. 两块板分别设角色和地址（在串口里敲）：
   ```
   cfg role air          # 一块设 air（机载）
   cfg role gcs          # 另一块设 gcs（地面站）
   save                  # 存 NVS
   reset                 # 重启生效
   ```
2. 重启后敲 `status`：两块板都应显示 `协议: 本机=v2 对端=v2`（对端还没通信过时显示「未知」，正常）
3. 敲 `scan`：应能看到邻居 + 信号强度（RSSI）
4. 敲 `ping <对端 node_id>`：应返回 RTT

> node_id 是第一次上电按 MAC 自动派生的、每块板唯一。看不清就在 `status` 里看。

> 开机都停在慢速窗（SF9）是正常的：非 GCS 的板子要停在这一档等信标。GCS 每 5s 发一次信标，
> 所以 A/B 两块板开机后最多 5 秒，`status` 的「速率」行就该显示 `ADR 对齐=是`；
> 一直显示 `对齐=否` 且 `失步` 在涨 = 没收到信标（GCS 那块板开了吗？距离多远？天线接好了吗？）。

## 6. 常见现象对照表

| 现象 | 先看什么 |
|---|---|
| 串口全是乱码 / 没输出 | 波特率 115200？USB 是数据线吗？整片擦除过吗？ |
| 每 5 秒重启 | `status` 的 `wdt复位` 在涨 → 看门狗（此 bug 已修，确认刷的是最新固件） |
| `射频: 就绪=否` | ① 先看初始化返回码：若是 `-2` = 芯片型号校验没过（RadioLib 拿「芯片自报型号」比对）→ 依次把 `firmware/src/drivers/radio.cpp` 的驱动类改成 `LLCC68`、再改 `SX1268`，每次重编（默认已是 `SX1262`，这块模块通常用它能过；依据见 `docs/references/LLCC68_E220-900M22S.md` §3）② 接线/供电（模块 1.8~3.7V；天线要先装）③ `cfg freq/sf/power` 非法（频率须 862~930；SF 必须与带宽配对：BW125→SF≤9、BW250→≤10、BW500→≤11 —— Web/CLI 已自动拦截非法组合） |
| 两机通不上 | ① `ver`：两块板协议版本一样吗？② 链路行 `认证失败` 在涨 = 密钥不一致（`crypto off` 或设同一个密钥）③ 驱动层有丢包 = 硬件/接线 |
| 能通但很慢 | 看链路行 `占空比超限放行`/`限流丢弃`：这是法规 10% 占空比的合规行为，不是 bug |
| 时通时不通 | 速率行 `ADR 对齐=否` 或 `失步` 在涨 = 没收到 GCS 信标（GCS 那块板开着吗？距离多远？） |
| 重启后对面收不到 | 看链路行 `重同步`：应涨 1 次然后恢复正常（这是特意修的，若「重启后就永久发不出去」才是 bug） |

---

## 7. 两条安全红线

1. 先装天线再上电，尤其是设了高功率（`cfg power 22`）之后
2. 别在室内两台板贴着（<1 米）长时间满功率发射：容易互相阻塞、也可能过驱动前端

---

## 8. 什么时候停下来找我

- 串口一点输出都没有（不是配置问题，是硬件/工具链问题）
- 两块板 `ver` 显示协议版本不一致（说明固件刷混了）
- `status` 三层里某一层持续涨、而你看不懂那行是什么意思 —— 把那行原样发我

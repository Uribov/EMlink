# EM Studio —— EMlink 桌面调试台（方案定稿 v3）

> 定稿日期：2026-10-17 ｜ 状态：**方案定稿 v3**（第一轮 5 项 + 第二轮 4 项 + 本轮"模式热切换"已并入），待开工
> 一句话：**电脑上的 EMlink 控制台** —— 图形化调参 + 诊断台 + MAVLink 强行编解码 + USB 烧录 + 多设备标签页

---

## 0. 人话版（给不看技术细节的人）

**EM Studio 是电脑上的 EMlink 驾驶舱**，插上 USB 就能干四件事：

1. **点着调参**（跟手机网页一个样：下拉框、滑块，改完点保存）——调参**不靠敲命令**；
2. **看复杂信息**：一个"诊断台"，把板子的自检/统计/报错摊开，将来固件加了模块间互查，**直接告诉你哪个模块出了问题**；
3. **强行编解码调试**（你最想要的）：随便打一段话，强行打成 MAVLink 帧发出去；另一头收到后**不管认不认识这条消息，强行拆开还原**给你看 —— 用来验证"空口通不通、数据有没有原样到"；
4. **一键 USB 烧录固件**。

还能**同时开多块板**（一个设备一个标签页），所以能"一块板当飞机、一块板当地面站"，**不上飞机就把链路调明白**。

**两种模式像两副眼镜，随时换戴，不用拔线** —— 但同一时刻只有一副在工作（不会两种数据混着看花眼）。

## 2. 技术栈（已定）

| 层 | 选型 | 说明 |
|---|---|---|
| 运行方式 | **纯 `.py` 轻量**（`python3 app.py`） | 不打包；改代码即生效 |
| 外壳 | **pywebview** | 系统 WebView（Linux WebKitGTK / Win WebView2 / macOS WKWebView）→ 跨三平台 |

| MAVLink | **pymavlink**（v20）**＋ 自写帧解析** | 常规消息用 pymavlink；"强行编解码"用自写帧层（不查方言表） |
| 烧录 | 调 `tools/flash_batch.sh` | 单块板：`--port <口> -y` |

## 3. 两种模式：**热切换，同一时刻只跑一种**（本轮修订）

```
        串口（保持连接，不拔不断）
                  │
            ┌─────┴─────┐
            │  分发器    │  ← 一个"当前模式"开关决定字节往哪走
            └─────┬─────┘
        ┌─────────┴─────────┐
   [配置模式]（默认）    [MAVLink 解码模式]
   字节 → CLI 解析器       字节 → MAVLink 帧解析器
   （MAVLink 帧直接丢弃）   （文本直接丢弃）
```

- **不用断开连接**：随时点顶部开关换视图，串口一直开着（用户 2026-10-17 修订）；
- **不同时工作**：分发器保证同一时刻只有一种解析器在吃字节，另一种的数据**直接丢弃** —— 这正是"不分串也能不糊"的关键；
- **切换瞬间的卫生**：切模式时**复位另一种解析器的状态**（丢掉可能被切一半的帧/行），避免半截数据污染新视图；
- **两个模式各自的独占行为**：① 配置模式下若板子正在往 USB 吐 MAVLink，那些字节被丢掉（不显示）；② 解码模式下 CLI 的文本回显被丢掉。想两者都看，只能靠"切来切去对时间线"——这是"不同时工作"的代价，用户已知并接受。
- **唯一真需要断开的是烧录**：烧固件要独占串口（见 §6），那时会明确提示并自动断开。

**技术事实（已查实）**：板子 `usb_task` 在**字节层**分流（`0xFD/0xFE` → MAVLink 帧；其余 → CLI 文本），两者共用同一个 `Serial`（靠一把互斥锁防交叉）。所以应用侧按首字节自己分流也是可行的 —— 但按用户决定，**同一时刻只处理一种**，不做并行双视图。

## 4. 图形化调参 + 诊断台

**调参以图形控件为主**（与网页同款）：角色 / 节点号 / 频率（整数+小数下拉）/ SF / BW / CR / 功率 / 维护延时 / 密钥 → 自动 `get` 回填 → 就地改 → `set` → 「保存」/「保存并重启」。

**CLI 定位 = 诊断台**（不是给你敲命令用的，是**看复杂信息**用的）：

| 视图 | 内容 |
|---|---|
| 三层状态 | `status` 的驱动 / 中间 / 应用三层，分组卡片 + 关键数字红黄绿标注 |
| 统计 | `stats`（fwd / dup / ttl / rssi / snr / heap / wdt / rf_reinit） |
| 原始终端 | 原样输出（保留手敲入口，供高级用户） |
| **诊断归因（预留位）** | 将来固件加「模块间互查」后，按**模块**分组报错，**一句话给出"谁出了问题"**（例：射频层 E220 未响应 err=-2 · 链路层 占空比超限 3 次 · 应用层 sysid 撞号 1）。桌面端解析+高亮，结论由固件产出 —— 接口开工时一起定。 |

## 5. MAVLink 强行编解码调试器（核心功能）

**发送**：输入任意文本（或 hex）→ 选/自定 `msgid`、`sysid`、`compid`、`target_sysid` → 应用组 MAVLink v2 帧 + 算 CRC → 从串口发出。

**接收（强行解码）**：不查方言表，按帧结构硬拆 `len / seq / sysid / compid / msgid / payload`，显示 **hex + 文本还原 + CRC 校验结果** —— 用来验证数据是否原样透传。

**可行性依据（已读板子源码确认）**：`mav_router.cpp::mav_crc_ok()`

```c
uint8_t crc_extra = 0;
const mavlink_msg_entry_t* e = mavlink_get_msg_entry(msgid);
if (e) crc_extra = e->crc_extra;      // ← 方言表里没有的 msgid：crc_extra 就是 0
```

→ 板子对**自造消息**按 `crc_extra = 0` 校验，所以：**表里没有的 msgid 用 0；表里有的用真值**（应用自动查表决定）。

**三条边界（诚实）**：
1. **空口端到端要等 E220** —— 现在只能验"电脑 → 板子"这段（板子侧统计/日志能看到帧进来）；
2. **对端要 GCS 角色**才能从它的 USB 看到帧（AIR 的 USB 面向飞控 UART）；
3. 路由看 `target_sysid`，调试时留 **0（广播）** 最省心。

**配套开关**：「模拟心跳」（每秒一条 HEARTBEAT）+「一键请求参数/遥测」，让电脑单独就能把通路搅活。

## 6. USB 烧录固件

- 界面：选设备 → 固件来源（用现有产物 / 先编译再烧 / 指定 `.bin`）→「开始烧录」→ 实时进度 + 结果；
- 行为：**烧录前自动断开该设备**（串口独占，界面明确提示）；调 `tools/flash_batch.sh`（自带整片擦除、校验、结果表）；
- 依赖：`esptool.py`（pipx 4.8.1，**带 stub**；系统 `esptool` 是坏的 → 写死用前者）+ 可选 `pio`；
- 不做：批量烧录（那是 `--all` 的事）。

## 7. P0 功能清单

1. **设备区 + 多设备标签页**：枚举/刷新/连接/断开；每设备一标签页；按**序列号**找回设备（不认 `ttyACM0`）；被占用时明确提示。
2. **图形化参数区**（§4）：读写 + 保存 + 保存并重启。
3. **诊断台**（§4）：三层状态 + 统计 + 原始终端 + 诊断归因预留位。
4. **MAVLink 解码模式**（§5）：看 / 发 / 强行编解码 / 模拟心跳 / 一键请求。
5. **USB 烧录**（§6）。
6. **模式热切换**（顶部开关；不用断开；同一时刻只跑一种；切时复位另一侧解析器状态）。

## 8. 界面与动效（极简顺滑 · 同源高级分支）

**同源规则**：`webui.h` 的 CSS 是**唯一源**（深色底、纯黑白灰、1px 发丝线、零圆角、无阴影、大写宽字距小标签、反色实心主按钮）；桌面端新增样式只写 `app.css`，**不改源**。

**动效（可整体关）**：状态点脉冲呼吸（呼应板上彩虹灯）；参数改动数值滚动 + 边框亮一下；连接/断开状态条滑入滑出；RSSI/fwd 每秒推进迷你折线；解码模式新帧淡入 + 高亮一次 + 频率柱生长；模式切换：两个视图交叉淡入（150ms）。**不做**：渐变、发光、粒子、弹跳、3D。

## 10. 关键实现点与坑

1. **命令串行 + 等回显**（CLI 行缓冲 256B）；轮询节流（`status`/`stats` 各 1s 错开）。
2. **分发器是唯一入口**：任何模式切换都先复位两侧解析器状态（丢半截帧/行）。
3. **回显不是答案**：剔除回显行再解析结果。
4. **不往 CLI 送二进制**（固件有 500ms 卡帧自恢复，但会吞一帧）。
5. **板子复位后按序列号找回设备**。
6. **串口独占**：只有烧录会强制断开，其余时候连接一直保持。
7. **跨平台只依赖 pyserial 字段**，不读 udev。
8. **WiFi 维护模式与 USB CLI 互不影响**（两条独立通路）。

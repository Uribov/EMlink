## 0. 简介

EM Studio 是电脑上的 EMlink 驾驶舱，插上 USB 就能干五件事：

1. 点着调参（跟手机网页一个样：下拉框、滑块，改完点保存）—— 调参不靠敲命令；
2. 看复杂信息：一个「诊断台」，把板子的自检/统计摊开成分组卡片，出问题时直接告诉你哪一层出了什么；
3. 强行编解码：随便打一段话，强行打成 MAVLink 帧发出去；另一头收到后不管认不认识这条消息，强行拆开还原给你看 —— 用来验证「空口通不通、数据有没有原样到」；
4. 一键 USB 烧录固件（带进度条，自动让出串口再重连）；
5. 会话日志导出（txt / json，出问题把文件发给别人复现）。

还能同时开多块板（一个设备一个标签页），所以能「一块板当飞机、一块板当地面站」，不上飞机就把链路调明白。

两种模式像两副眼镜，随时换戴，不用拔线 —— 但同一时刻只有一副在工作。

## 2. 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 运行方式 | 纯 `.py` 轻量 | 不打包 AppImage；改代码即生效；VSCode F5 可断点 |
| 外壳 | pywebview | 系统 WebView（Linux WebKitGTK / Win WebView2 / macOS WKWebView）→ 跨三平台 |
| 界面 | HTML + CSS + 原生 JS | 样式与 `webui.h` 逐字符同源，桌面端增量只写 `app.css` |
| 串口 | pyserial | 三平台端口通吃；读 VID/PID/序列号 |
| MAVLink | 自写帧层 + pymavlink | 强行编解码走 `mav_raw.py`（不查方言表）；`crc_extra` 查表，查不到按 0 |
| 烧录 | 直接调 `esptool.py` | `backend/flasher.py` 封装：`subprocess.Popen` 逐行读进度、无 `shell=True`、共享超时 |

> v3 的偏差更正：原文写「调 `tools/flash_batch.sh`」，实际改为直调 `esptool.py` —— 桌面端要的是单块板的实时进度，走脚本反而多一层解析。

## 3. 两种模式：热切换，同一时刻只跑一种

```
        串口（保持连接，不拔不断）
                  │
            ┌─────┴─────┐
            │  分发器    │  ← 「当前模式」决定字节往哪走
            └─────┬─────┘
        ┌─────────┴─────────┐
   [配置模式]（默认）    [MAVLink 解码模式]
   字节 → CLI 解析器       字节 → MAVLink 帧解析器
   （MAVLink 帧丢弃）       （文本丢弃）
```

- 不断开：顶部开关随时换视图，串口一直开着；
- 不同时工作：分发器保证同一时刻只有一种解析器在吃字节；
- 切换卫生：切模式时复位另一侧解析器状态，避免半截帧/行污染新视图；
- 唯一需要断开的是烧录：固件烧录独占串口，界面明确提示并自动断开、烧完自动重连。

技术事实（已查实）：板子 `usb_task` 在字节层分流（`0xFD/0xFE` → MAVLink 帧；其余 → CLI 文本），共用同一个 `Serial`（互斥锁防交叉）。应用侧也能按首字节分流，但按定稿只处理一种。

## 4. 图形化调参 + 分层状态台

调参（与网页同款控件）：角色 / 节点号 / 频率（整数 + 十分位 + 百分位 + 千分位四个下拉）/ SF / BW（带配对校验提示）/ CR / 功率 / 维护延时 / 密钥（唯一手输项）→ `get` 回填 → 就地改 → `set` → 「保存」/「保存并重启」。

状态台：每 2 秒静默读一次 `status`（不回显、不进诊断台输出区），解析成三层分组卡片：

| 层 | 内容 |
|---|---|
| 驱动层 | 射频就绪/模块在线、请求超时、收包队列丢、射频请求丢、UART/USB 丢 |
| 中间层 | 占空比、认证失败、重放丢弃、重同步、限流、协议不一致、去重/TTL/路由/分片淘汰、发送队列丢、ADR 对齐、信标、失步、SF、adr 开关 |
| 应用层 | 遥测降频、sysid/node_id 撞号、heap、wdt 复位、射频重建 |

诊断归因（v3 预留位 → 已实现）：`backend/prober.py::diagnose()` 表驱动规则，命中才显示一条结论，无命中不显示：

> 射频模块未检测到 / 射频未就绪 / 加密认证失败 / 协议版本不一致 / 重放攻击丢弃 / 出现环路或重复包 / 发送队列丢弃 / sysid 撞号 / node_id 撞号 / WDT 复位 / ADR 未对齐（需有邻接活动才判定，避免单机误报）

分层折叠（2026-10-19 追加）：三层的标题行可点击折叠，折叠后只留「状态点 + 层名 + 折叠符号」一行，给下方诊断台输出区腾出空间。折叠状态存在 `state.collapsedLayers`（Set），切换设备 / 重连后保持；圆点颜色照常反映该层最坏等级，所以折起来也不会漏看异常。

链路指标条（2026-10-19 追加）：`ping` 回包（`通：rtt=130ms rssi=-98dBm`）与 `scan` 回包（`最近收包 rssi=-98 snr=10`）里的数字在前端自动提取，显示为 RTT / RSSI / SNR / 采样时刻 四格。

| 指标 | 绿 | 黄 | 红 |
|---|---|---|---|
| RTT | ≤ 300 ms | ≤ 800 ms | > 800 ms |
| RSSI | ≥ −100 dBm | ≥ −112 dBm | < −112 dBm |
| SNR | ≥ 5 dB | ≥ 0 dB | < 0 dB |

阈值是 LoRa/SF7 的经验值（解调门限 SNR ≈ −7.5 dB），不是固件定义的判据。颜色只落在一个 5px 状态点上，数字保持单色。邻居表行（`邻居：187 rssi=-90 age=3s`）与超时行不参与解析，避免污染主指标；无数据时整条隐藏，不占版面。


## 5. MAVLink 强行编解码

发送：输入文本或 hex → 指定 `msgid`/`sysid`/`compid`/`target` → 组 MAVLink v2 帧 + 算 CRC → 串口发出。

接收：不查方言表，按帧结构硬拆 `len / seq / sysid / compid / msgid / payload`，显示 hex + 文本还原 + CRC 校验结果；CRC 错也照解并标 `crc_ok=false`。

帧格式：`0xFD · len · incompat · compat · seq · sysid · compid · msgid(3LE) · payload · crc(2LE)`
CRC：CRC-16/MCRF4XX（初值 `0xFFFF`，范围 `len…payload`，最后吃 `crc_extra`）

`crc_extra` 规则（与固件一致）：先查方言表 `crc_extra` → 查不到用 0。
依据 `mav_router.cpp::mav_crc_ok()`：方言表里没有的 msgid，`crc_extra` 就是 0。

配套：模拟心跳（1 秒一条 HEARTBEAT）、一键请求参数、导出全部帧 JSON；帧表右键可单独导出该帧（JSON / 文本）或删除该帧，工具条上有「全部删除」。单帧导出只带那一帧（不含会话日志与状态快照），文件名带 `frame<msgid>` 便于区分。

边界（2026-10-19 实测后更新）：

1. 空口端到端已验证 —— RXEN/TXEN 引脚接反修复后打通，对端解出自造帧 `msgid=200/201/202`，payload 原样还原、CRC 全过；
2. 对端要 GCS 角色才能在 USB 上看到帧 —— AIR 的 USB 面向飞控 UART（实测一 GCS 一 AIR 双向 ping 通，此前的「必须同 role」是观测盲区）；
3. 路由看 `target_sysid`，调试时留 0（广播）最省心。

## 6. USB 烧录固件

- 流程：选 `.bin` → 「开始烧录」→ 自动断开串口 → esptool 写 flash → 自动重连；
- 参数：默认只写 app（`write_flash --flash_mode qio --flash_size 4MB 0x10000 <bin>`）；勾「整片烧录」则 `erase_flash` 后从 `0x0` 写（必须选合并镜像，否则变砖）；
- 进度：实时解析 esptool 输出的百分比，进度条 + 数字；烧录中禁用连接/断开/刷新/选文件，关闭标签被拦截；
- 依赖：`esptool.py`（pipx 4.8.1，带 stub；系统 `esptool` 是坏的）；
- 实测：真机 11% → 100%，7.0 秒完成，烧完配置（角色/node_id）保住、射频正常在线。

## 10. 关键实现点与坑

1. 命令串行 + 等回显（CLI 行缓冲 256B）；状态轮询用 `silent` 查询，不回显、不进输出区。
2. 静默查询必须是唯一收口：`SerialLink._handle_line()` 是入队前的唯一过滤点，`#led` 推送行和 `#` 开头的行在这里拦掉。
3. 回显不是答案：剔除回显行再解析结果。
4. 串口独占：只有烧录强制断开；其余时候连接一直保持。
5. 板子复位后按序列号找回设备，不认 `ttyACM0`。
6. 外部释放串口信号必须是 `SIGRTMIN+3`（37）—— `SIGUSR1`(=10) 被 WebKit/JavaScriptCore 用作 GC 通知，抢占会让进程崩溃。handler 只 `Event.set()`，实际 I/O 在守护线程。
7. WebKitGTK 原生 `<select>` 不吃 `background:transparent` → `appearance:none` 自绘箭头。
8. 状态卡长文本溢出：flex 项必须 `min-width:0`，否则 `text-overflow:ellipsis` 完全失效。
9. 三角灯不能同相：前端改为照抄板子推来的颜色 + CSS `steps` 动画，放弃严格同相换平滑无半亮。
10. 烧录必须 QIO：封装内 flash 的 S3 在 DIO 下 bootloader 读不到 app（表现为能连、串口零字节）。
11. 跨平台只依赖 pyserial 字段，不读 udev。
12. WiFi 维护模式与 USB CLI 互不影响（两条独立通路）。

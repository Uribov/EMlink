# airtime —— LoRa 空中时间计算

## 职责

给定帧长与调制参数（SF/BW/CR），算出这一帧占住空口多少毫秒（Semtech 官方公式）。
全工程只此一处算空中时间：占空比预算、ACK 超时、速率/吞吐判断都必须用它，禁止再写经验粗估。

它是全工程空口时间账本的唯一来源，改公式等于同时改动 duty、mac 和 ADR 三个模块的判断依据。


## 依赖

- 无（纯整数计算，不依赖 RadioLib、不碰硬件、可在主机上直接编译单测）
- 由 `drivers/radio.cpp` 使用，包装成 `radio_airtime_ms()`（= 按当前实际调制参数算）；上层模块只用那个包装

零依赖是它的价值所在：公式对不对可以在 PC 上一次性验证，不用上板。


## 公式（LoRa，显式头 / CRC 开 / 前导 8 符号）

```
Tsym(us) = 2^SF * 1000 / BW(kHz)
DE       = 1 当 SF>=11 且 BW=125kHz（低速率优化），否则 0
nPayload = 8 + ceil( (8*PL - 4*SF + 28 + 16*CRC - 20*IH) / (4*(SF - 2*DE)) ) * CR
           PL=帧长(字节)、IH=0(显式头)、CRC=1、CR=5..8（即 4/5..4/8）；括号内 ≤0 时按 0 计
ToA(us)  = Tsym * (nPayload + 8 + 4.25)
返回     = ceil(ToA / 1000) 毫秒
```

公式里 DE（低速率优化）只在 SF≥11 且 BW=125kHz 时置 1，这是 LoRa 规范里的强制项。


## 对外接口

见 `airtime.h`：`uint32_t airtime_ms(uint32_t len_bytes, uint8_t sf, float bw_khz, uint8_t cr)`

- 参数非法（SF<7 或 >12、CR<5 或 >8、BW≤0）→ 返回 0
- 调用方必须把 0 当「算不出」处理（例：按满预算记账），不可当 0ms 用

返回 0 代表参数不合法，不是「这帧不占空口」，调用方要区别对待。


## 验收

与审查日志 P1-2 表格逐值吻合（BW125 / CR4/5，本模块返回的是向上取整值）：

| 帧长 | SF7 | SF10 |
|---|---|---|
| 16B（ACK/信标） | 52ms | 330ms |
| 179B（满密文分片） | 287ms | 1641ms |
| 195B | 313ms | 1805ms |
| 200B（MTU 满帧） | 318ms | 1846ms |

这几个值同时也是 mac 的 ACK 超时和 duty 预算的基准，改动公式后要重新对齐这张表。

## 当前实现架构（供人和子 agent 阅读）

### 简介

把「发这一帧要在空中占多久」从经验粗估（原来 `5 + len*300/1000`，200B 算 65ms，实际差 5~28 倍）换成官方公式的整数实现。


### 实现要点

- 全整数：`tsym_us = (1<<sf) * 1000 / bw`；载荷符号数用 `(num + den - 1)/den` 向上取整；4.25 符号写成 `tsym_us * 17 / 4`
- 结果向上取整到 ms —— 保守方向（宁可多记占空比，不可少记）
- `num <= 0` 时载荷符号数按 0 处理（极短帧）；`bw<1kHz` 直接返回 0
- 溢出：SF12/BW125 满帧 ≈ 7.2s，us 级最大 ~14e6，远小于 uint32 上限

全整数实现是为了在主机上可编译、结果可复现；向上取整则是刻意选的保守方向。


### 关键数字（BW125/CR4/5，调参/写文档时的基准）

| 帧 | SF7 | SF10 | SF11 | SF12 |
|---|---|---|---|---|
| 16B（ACK/信标） | 52ms | 330ms | 660ms | 1319ms |
| 200B（满帧） | 318ms | 1846ms | 4019ms | 7218ms |

两个直接结论：

1. SF10 下 ACK 帧自身就要 330ms → 写死 300ms 的 ACK 超时必然超时（P1-2 的根因）
2. 单帧 >5s 就发不完：SF12 的 200B 帧要 7.2s，超过任务看门狗 5s 超时；当前 NVS 允许 `sf=12`，属配置面待收口项（见审查日志后续项，非本次修复范围）

这张表是最常被引用的数字：mac 的 ACK 超时、duty 的单帧预算、用户选 SF 时的取舍都看它。


### 不直接用 RadioLib getTimeOnAir 的原因

`duty` 模块刻意不依赖 RadioLib（纯逻辑、可主机单测），而公式本身就是 RadioLib 内部用的那一条 —— 自己实现能保证「预算账本」与「实际发送」用的是同一个数。

自实现的目的是让算账和实发共用一套数字，不是重复造轮子。


### 主机单测（可复用）

`g++ -I<垫片> -I firmware/src/drivers at_test.c firmware/src/drivers/airtime.cpp`，垫片只需一个提供 `uint32_t` 的 `Arduino.h`；当前 15 项断言全过（含 SF11/SF12 的 DE 分支与非法参数）。
